# ตัววัดประสิทธิภาพในงาน NLP

การเลือกตัววัด (Metric) ที่เหมาะสมกับงานเป็นสิ่งสำคัญ เพราะตัววัดที่ไม่เหมาะสมอาจทำให้เข้าใจผิดว่าโมเดลดีทั้งที่ใช้งานจริงไม่ได้

## ตัววัดสำหรับงานจำแนก

จากตารางความสับสน (Confusion Matrix) ซึ่งนับ True Positive (TP), False Positive (FP), True Negative (TN) และ False Negative (FN) คำนวณตัววัดหลักได้ดังนี้
- Accuracy = (TP + TN) / ทั้งหมด วัดสัดส่วนที่ทำนายถูก แต่ใช้ไม่ได้ดีกับข้อมูลไม่สมดุล
- Precision = TP / (TP + FP) ในบรรดาที่โมเดลทำนายว่าเป็นบวก ถูกจริงกี่ส่วน
- Recall = TP / (TP + FN) ในบรรดาตัวอย่างที่เป็นบวกจริง โมเดลหาเจอกี่ส่วน
- F1-score = 2 × Precision × Recall / (Precision + Recall) ค่าเฉลี่ยฮาร์มอนิกของ Precision และ Recall

สำหรับหลายคลาส ใช้ Macro-F1 (เฉลี่ยแต่ละคลาสเท่ากัน) หรือ Weighted-F1 (ถ่วงน้ำหนักตามจำนวนตัวอย่าง) ตัวอย่างเช่น ระบบกรองสแปมที่ไม่อยากกรองอีเมลดีทิ้งควรให้ความสำคัญกับ Precision

## ตัววัดสำหรับงานสร้างข้อความ

BLEU ใช้กับการแปลภาษา ROUGE ใช้กับการสรุปความ ส่วน Perplexity วัดว่าโมเดลภาษา "แปลกใจ" กับข้อความทดสอบมากน้อยเพียงใด ค่ายิ่งต่ำยิ่งดี BERTScore เปรียบเทียบความคล้ายเชิงความหมายด้วย Embedding แทนการเทียบคำตรง ๆ จึงรับมือกับการเปลี่ยนถ้อยคำได้ดีกว่า

## การประเมินระบบ RAG

ระบบ RAG ควรประเมินแยกสองส่วน ส่วนค้นคืน (Retrieval) ใช้ตัววัด เช่น Hit Rate หรือ Recall@k คือสัดส่วนของคำถามที่ Chunk ที่ถูกต้องอยู่ใน k อันดับแรก และ MRR (Mean Reciprocal Rank) ที่ให้คะแนนสูงเมื่อคำตอบอยู่อันดับต้น ส่วนการสร้างคำตอบ (Generation) ประเมินความซื่อตรงต่อบริบท (Faithfulness) ว่าคำตอบอิงจากเอกสารจริงหรือไม่ และความเกี่ยวข้องของคำตอบ (Answer Relevance) กับคำถาม

ชุดคำถามทดสอบที่ดีควรมีทั้งคำถามที่เอกสารตอบได้ และคำถามที่เอกสารไม่มีคำตอบ เพื่อตรวจว่าระบบกล้าปฏิเสธเมื่อไม่มีข้อมูล แทนที่จะเดาหรือแต่งคำตอบขึ้นมาเอง

## Human Evaluation

ตัววัดอัตโนมัติไม่สามารถจับคุณภาพทุกด้านได้ งานสำคัญจึงควรให้มนุษย์ประเมินด้านความถูกต้อง ความลื่นไหล และความเป็นประโยชน์ร่วมด้วย
